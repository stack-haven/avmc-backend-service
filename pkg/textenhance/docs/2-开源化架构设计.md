# ark-lexnorm 开源化架构设计

> 输入：`0-能力定位.md`（能力基线）+ `1-代码评分报告.md`（39.5/100，34 项问题）
> 命名：**ark-lexnorm**（文本词法规范引擎）
> 目标：重构为可发布到 pkg.go.dev 的独立库，目标评分 ≥ 90
> 原则：**保留正确的骨架（Strategy / Pipeline / Registry），重做实现层与 API 边界**

---

## 零、设计总纲

### 0.1 三条不可妥协的约束

| # | 约束 | 理由 |
|---|---|---|
| 1 | **core 只依赖 stdlib** | 一个文本库不该拖进 kratos。零依赖是开源采纳率的第一杠杆 |
| 2 | **导出的东西必须能长期维持** | 当前导出了 EnhancementContext / Policy / Snapshot 的全部字段，等于把内部表示焊死在 API 上。v1 之前必须收窄 |
| 3 | **文档承诺 = 代码行为** | 评分报告里最严重的是「宣称 HA / 线程安全但实测失败」。宁可少承诺 |

### 0.2 深模块原则（窄接口 / 厚实现）

当前是**浅模块**：14 个包、暴露 40+ 个导出类型，但用户要写 6 行样板才跑通一次增强。
目标是**深模块**：
- **对 99% 用户**：1 个 import、2 个 API（`New` / `Enhance`）；
- **对扩展者**：1 个接口（`Processor`）+ 1 个注册函数；
- **对运维**：1 个 Hook 接口 + `slog`。

### 0.3 命名

按 `0-能力定位.md` 已锁定：`ark-lexnorm`。
- **ark**：组织前缀，表明归属 Ark 体系；
- **lexnorm**：lexical normalization，学术界真实任务名（W-NUT shared task），定位精准、可搜索；
- 中文名：**文本词法规范引擎**，简称 **文本规范引擎**；
- **不使用** `textenhance` / `textpipe` / `lexifix` 等备选——「enhance」语义模糊且暗示不可验证的承诺；
  「pipe」只描述形态不描述能力。

旧备选对比表（已淘汰，仅留作历史记录）：


| 候选 | 评价 |
|---|---|
| `textenhance` | ❌ 已淘汰：语义模糊，暗示不可验证的承诺 |
| `textpipe` | ❌ 已淘汰：只描述形态不描述能力 |
| `lexifix` | ❌ 已淘汰：备选，仍偏「词表」 |
| **`ark-lexnorm`** | ✅ **已锁定**：lexical normalization 是 NLP 真实任务，定位精准 |

- `internal/` 承接所有不想承诺稳定性的东西。

## 二、设计模式选型（12 个，逐一给出理由与落点）

| # | 模式 | 落点 | 解决评分报告的哪些问题 |
|:--:|---|---|---|
| 1 | **Facade** | `Engine` / `New` / `Enhance` | A1 A2 |
| 2 | **Strategy** | `Processor` 接口（保留，签名改造） | 保留优点 + A5 |
| 3 | **Chain of Responsibility / Middleware** | `Middleware func(Handler) Handler` | 三套横切机制合一、C1 C12、A5 A6 |
| 4 | **Builder** | `lexicon.Builder` / Functional Options | C2 性能（一次建索引） |
| 5 | **Immutable Snapshot + Flyweight** | `lexicon.Lexicon` 跨请求共享只读 | A3 S1 性能 |
| 6 | **Abstract Factory / Registry** | 类型安全 `Registry` + `Descriptor` | A4 C2 插件协议 |
| 7 | **Object Pool** | `sync.Pool` 复用 `State` / rune buffer | 227k allocs |
| 8 | **Null Object** | `noopProcessor` / `nopHook` | 去掉 `llm_reserved` 空壳 |
| 9 | **Observer → Hook（收敛）** | 单方法 `OnEvent(Event)` + `BaseHook` | A6 S4 |
| 10 | **Functional Options** | 全部构造函数（保留，已做对） | 保留优点 |
| 11 | **Value Object** | `Result` / `Change` / `Span` 全部值语义 | A2 A3 S1 C10 |
| 12 | **Atomic Swap** | `atomic.Pointer[Lexicon]` 热更新 | 原 M6d 目标，10 行搞定 |

> **被砍掉的模式**：Decorator（`ObservingProcessor`）—— 被 Middleware 完全取代。
> 一个库只该有**一种**横切扩展机制，两种会让用户困惑「我该用哪个」。

## 三、核心 API 设计

### 3.1 Facade：三行跑通

```go
package lexnorm

// Engine 是并发安全的、可长期持有的增强引擎。
// 零值不可用；用 New 构造。
type Engine struct { /* 私有 */ }

func New(opts ...Option) (*Engine, error)

// Enhance 对单条文本执行流水线，返回不可变结果。
// 并发安全：可被任意多 goroutine 同时调用。
func (e *Engine) Enhance(ctx context.Context, text string, opts ...CallOption) (Result, error)
```

用户侧：

```go
eng, err := lexnorm.New(
    lexnorm.WithProfile("default"),                  // Profile 替代多租户抽象
    lexnorm.WithPreset(lexnorm.PresetStandard),
    lexnorm.WithLexicon(lexicon),                    // 调用方注入词表
)
res, err := eng.Normalize(ctx, "default", "呃，佘丽群明天开会")
fmt.Println(res.Text)      // "周丽群明天开会"
fmt.Println(res.Changes)   // [{Span:{0,3} From:"佘丽群" To:"周丽群" ...}]
```

**对比当前**：6 行 + 5 个概念 → 2 行 + 1 个概念。

### 3.2 Result：不可变值对象（替代「从入参读结果」）

```go
type Result struct {
    Text      string        // 增强后文本
    Original  string        // 原文
    Changes   []Change      // 已应用 + 建议（Applied 字段区分）
    Status    Status        // Success / Partial / Canceled
    Duration  time.Duration
    Steps     []StepTiming  // 每步耗时（替代 map，确定顺序、零分配）
    Err       error         // Partial 时的聚合错误（errors.Join）
}

type Change struct {
    Span       Span     // ⭐ 在 Original 中的字节区间（C10）
    From, To   string
    Action     Action   // 枚举类型而非 string（编译期安全）
    Kind       Kind
    Source     Source
    Confidence float64
    Applied    bool     // ⭐ 区分「已替换」与「仅建议」
    Reason     string
}

type Span struct{ Start, End int }   // 半开区间 [Start, End)
```

**变更点**：
- `Action string` → `type Action uint8` + `String()`：拼错常量在编译期挂掉；
- 加 `Span`：调用方能做高亮 / diff / 撤销；
- 加 `Applied`：解决 C4「4009 条 Change 里分不清哪 4 条真的生效」。

### 3.3 Strategy：Processor 返回 error

```go
type Processor interface {
    Name() string
    Process(ctx context.Context, s *State) error
}
```

**三个改动的理由**：
1. **返回 error** → 错误处理策略上移到 Pipeline（`ErrorPolicy: ContinueOnError | FailFast`），
   9 个 processor 不再各自复制 HA 样板（A5）；
2. **`*State` 而非 `*EnhancementContext`** → 名字更准确，且字段全部私有；
3. **文档明确「State 由单 goroutine 独占」** → 删掉 mutex，直面 S1，
   顺带省掉每次 append 的锁开销。

`State` 的公开面只有方法：

```go
func (s *State) Text() string
func (s *State) Lexicon() lexicon.Lexicon
func (s *State) Config() Config
func (s *State) Replace(span Span, to string, meta ChangeMeta)  // ⭐ 唯一的文本修改入口
func (s *State) Suggest(span Span, to string, meta ChangeMeta)
func (s *State) Lock(span Span)
func (s *State) IsLocked(span Span) bool                        // O(log n) 区间树
```

> **`Replace(span, ...)` 是这次重构的枢纽**。
> 当前 processor 各自 `strings.ReplaceAll` + 手写 Change + 手写 Lock（抄了 6 遍，错了 6 遍）。
> 收敛到 State 唯一入口后：偏移映射、锁检查、Change 记录、级联防护全部一处实现、一处测试。
> 这直接消灭 C3 / C9 / C10 和 P1 的「ReplaceAll 级联替换」。

### 3.4 Middleware：统一横切

```go
type Handler func(ctx context.Context, s *State) error
type Middleware func(Handler) Handler

// 内置
func Recover() Middleware      // panic → *PanicError（保留原始 value + stack，修 C12）
func Timing() Middleware       // 单点计时（消除 Pipeline/Decorator 双重计时）
func WithHooks(h ...Hook) Middleware
func Timeout(d time.Duration) Middleware  // ⭐ 可选而非强制（修 A7）
```

组合：

```go
eng, _ := lexnorm.New(
    lexnorm.WithMiddleware(
        lexnorm.Recover(),
        lexnorm.Timing(),
        lexnorm.WithHooks(hooks.NewSlog(logger)),
        myTracingMiddleware,   // ⭐ 用户可插入自己的，顺序自己定
    ),
)
```

**收益**：`ObservingProcessor` 的 re-panic hack、`Notify*` 三个自由函数、
`runOneStep` 的内联计时、`safeNotify` —— 四处代码合并为一个概念。

### 3.5 Hook：单方法接口

```go
type Event struct {
    Type      EventType   // PipelineStart / ProcessorStart / ProcessorEnd / PipelineEnd
    Processor string
    Duration  time.Duration
    Changes   int
    Err       error
    Result    *Result     // 仅 PipelineEnd 非 nil
}

type Hook interface{ OnEvent(context.Context, Event) }
```

6 方法 → 1 方法（A6）。`hooks.NewSlog` 默认**不打印文本内容**，
需显式 `hooks.WithText()` 才输出（S4 脱敏）。

### 3.6 Registry：类型安全 + 配置驱动

```go
// Descriptor 描述一个可被配置装配的 processor。
type Descriptor struct {
    Name    string
    Order   int                                       // ⭐ 顺序由 processor 自声明
    New     func(cfg json.RawMessage) (Processor, error)
    Default func() any                                // 默认配置（用于文档生成）
}

func Register(d Descriptor)                            // 全局内置
func (r *Registry) Register(d Descriptor) error        // 隔离实例
```

配置驱动装配（解决 C2 + 插件协议）：

```yaml
processors:
  - name: fuzzy
    config:
      auto_threshold: 0.80
      categories:
        PERSON: { auto: 0.65, suggest: 0.55 }   # ⭐ 业务阈值从 builtins.go 移到配置
  - name: phrase
    config:
      rules: [{ from: "个种籽", to: "颗种籽" }]   # ⭐ 业务规则从代码移到配置（A8）
```

**顺序由 `Descriptor.Order` 自声明**，取代 `DefaultProcessorOrder` 硬编码字符串数组——
第三方 processor 也能插进流水线的正确位置。

### 3.7 Lexicon：接口 + 索引

```go
package lexicon

type Lexicon interface {
    Entry(id EntryID) (Entry, bool)              // ⭐ O(1)，杀死 O(R×E)
    Lookup(text string) (Entry, bool)
    Relations(text string) []Relation
    All(yield func(Entry) bool)                  // Go 1.23 iterator，顺序确定
    Matcher() *Matcher                           // ⭐ 预建 Aho-Corasick
    Len() int
    Version() string
}

type Builder struct{ /* ... */ }
func (b *Builder) AddEntry(Entry) *Builder
func (b *Builder) AddRelation(Relation) *Builder
func (b *Builder) Build() (Lexicon, error)   // 一次性建全部索引
```

**Build 时一次性完成**（当前是每请求重复做）：
1. `EntryID → Entry` map（O(1) resolveTarget）；
2. 全部 pattern 的 Aho–Corasick 自动机（O(N+m) 多模式匹配）；
3. n-gram 倒排表（fuzzy 候选剪枝）；
4. 确定性排序（按 StandardText 字典序固化）。

热更新：

```go
type Store struct{ v atomic.Pointer[Lexicon] }
func (s *Store) Swap(nv Lexicon)     // 原 M6d PipelineManager，10 行
```

### 3.8 Errors：无 kratos

```go
var (
    ErrProcessorNotFound = errors.New("lexnorm: processor not found")
    ErrInvalidConfig     = errors.New("lexnorm: invalid config")
    ErrTextTooLarge      = errors.New("lexnorm: text exceeds limit")
)

type ProcessorError struct {
    Name string
    Op   string
    Err  error
}
func (e *ProcessorError) Error() string { ... }
func (e *ProcessorError) Unwrap() error { return e.Err }
```

调用方 `errors.Is/As` 判定。kratos 适配放到**业务侧**的一个 20 行转换函数里，
不进开源库。

### 3.9 Config：显式校验，拒绝静默降级

```go
type Config struct { /* 私有字段 + Getter */ }

func (c Config) Validate() error   // ⭐ 越界返回 error，不再静默 clamp 到 0（修 C5）
```

**行为契约变更**：
- 越界阈值 → `New` 返回 error（fail fast），而不是归零后全量替换；
- 空 processor 列表 → 真的是空流水线（修 C6，文档与行为对齐）；
- 需要宽容模式的调用方显式 `WithLenientConfig()`。

## 四、性能重构方案

| 问题 | 当前 | 目标方案 | 预期 |
|---|---|---|---|
| resolveTarget O(E) | 26.4 ms | Build 时建 ID map | O(1) |
| 多模式匹配 O(E×N) | 30.2 ms | Aho–Corasick 一次扫描 | O(N + matches) |
| fuzzy 全量滑窗 | O(E×N×L) | n-gram 倒排剪枝 + 长度过滤 + 早停 | 剪枝率 >95% |
| 每请求排序 | 每次 Process | Build 时固化 | 0 |
| R 次 ReplaceAll | R 遍全文 | 单次左→右扫描 + 最长匹配 | 1 遍 |
| IsLocked O(n²) | 线性 + 无界 | 有序区间集，二分 | O(log n) |
| 227k allocs | 每窗口 `string(rune[i:j])` | 字节偏移比较 + `sync.Pool` | 目标 <200 |
| Change 4009 条 | 无上限 | `MaxSuggestions` + 按置信度 top-K | 可控 |

**验收基线**（必须写进 `benchmark_test.go` 并纳入 CI 回归）：

| 场景 | 当前 | 目标 |
|---|---:|---:|
| 45 字 / 2000 词条 | 48.7 ms、11.4 MB、227,859 allocs | **< 200 µs、< 32 KB、< 200 allocs** |
| 1000 字 / 10000 词条 | 未测（预计 >1 s） | < 3 ms |

> 目标是 **~250× 提速**。听起来激进，但当前是 O(E×N) + 每请求重排序 + R 遍全文扫描，
> 换成 O(N) 自动机后这个量级是算法决定的，不是调优得来的。

## 六、迁移里程碑

> 原则：**每个里程碑独立可验证、可回滚**。`evie/tool` 侧用适配层挡住变更，
> 只在 M8 一次性切换。

| M | 主题 | 交付 | 验收 |
|:--:|---|---|---|
| **M1** | 止血 | 修 C1/C5/C6/C7/C8；gofmt + lint 清零；补 C1~C12 回归用例 | 现有 API 不变，测试全绿，lint 0 |
| **M2** | 解依赖 | 去 kratos、去 pkg/pinyin；`errors.go` 重写；独立 `go.mod` | `go list -deps` 只剩 stdlib |
| **M3** | 值语义 API | `Result` / `Change{Span}` / `Action` 枚举；`Engine` Facade | 新旧 API 并存，`Deprecated:` 标注旧的 |
| **M4** | State 收口 | 字段私有化 + `Replace/Suggest/Lock` 唯一入口；删 mutex 并文档化独占语义 | `-race` 全绿，C3/C9 消失 |
| **M5** | Middleware | Middleware 链替换 Decorator + 内联 recover + Notify*；Hook 收敛为单方法 | 删除 `observer.go` 中 ~120 行 |
| **M6** | 性能 | `lexicon.Builder` + ID 索引 + Aho–Corasick + n-gram 剪枝 + 区间锁 + Pool | 达成 §4 基线（<200µs / <200 allocs） |
| **M7** | 配置与插件 | `Descriptor` + YAML/JSON 装配；业务规则/阈值全部外置 | 内置 processor 默认值里无业务词 |
| **M8** | 开源发布 | 包重命名、英文文档、Example、Fuzz、Golden、CI、LICENSE、v1.0.0 | pkg.go.dev 页面完整；Go Report Card A+ |
| **M9** | 业务切换 | `evie/tool` 切到新 API，删适配层 | 端到端结果与旧版 golden 一致 |

**建议节奏**：M1+M2 一周内合并（止血 + 解依赖，风险最低收益最高）；
M3~M5 为一个 API 重构批次；M6 单独一个批次（有基准兜底）；M7~M9 收尾。

## 七、风险与权衡

| 风险 | 应对 |
|---|---|
| API 破坏性变更影响 `evie/tool` | M3~M5 期间新旧 API 并存 + `Deprecated:`；M9 才删旧的 |
| Aho–Corasick 自研有 bug | `match/` 独立包 + fuzz + 与暴力实现做差分测试（differential testing） |
| 「State 单 goroutine 独占」被误用 | 文档 + `go vet` 无法检测，改用**运行时 debug 断言**（build tag `lexnorm_debug` 下检查 goroutine ID） |
| 删掉 `llm_reserved` 影响规划 | 用 `Processor` 接口即可外部实现，不需要库内空壳；README 给 LLM 集成示例 |
| 重构期间业务停滞 | M1/M2 不改 API，业务可继续；重构在 feature 分支推进 |

## 八、重构前后对照（用户视角）

```go
// ===== 当前 (ark-lexnorm pre-refactor) =====
reg := builtins.NewDefaultRegistry()
policy := textenhance.DefaultPolicy()
policy.FuzzyAutoThreshold = 0.9              // ← 静默无效（C2）
pipeline, _ := textenhance.BuildPipeline(reg, policy,
    textenhance.WithObservers(observers.NewLoggingObserver(lg)))
ec := textenhance.NewEnhancementContext(text, lexicon, policy)
pipeline.Run(ctx, ec)                        // ← 无返回值
out := ec.Text                               // ← 从入参读；ec 不能复用；有 race
// 4009 条 Change，分不清哪条生效；48.7ms

// ===== 目标 (ark-lexnorm) =====
eng, err := lexnorm.New(
    lexnorm.WithProfile("default"),
    lexnorm.WithLexicon(v),
    lexnorm.WithFuzzy(lexnorm.FuzzyConfig{AutoThreshold: 0.9}),   // ← 真的生效
    lexnorm.WithMiddleware(lexnorm.Recover(), lexnorm.WithHooks(hooks.NewSlog(lg))),
    lexnorm.WithSteps(                                      // ⭐ 用户自定义处理项
        lexnorm.NoiseClean(), lexnorm.Disfluency(), lexnorm.AliasMap(),
        lexnorm.DeterministicMap(), lexnorm.PinyinCorrection(),
        lexnorm.FuzzyCorrection(), lexnorm.ContextualCorrection(),
        // lexnorm.LLMRefine(llmClient),  // ← 可选插入，未启用
    ),
)
res, err := eng.Normalize(ctx, "default", text)   // ← 并发安全、值返回
out := res.Text
for _, c := range res.Applied() { ... }      // ← 已应用；Suggestions() 取建议
// < 200µs
```
