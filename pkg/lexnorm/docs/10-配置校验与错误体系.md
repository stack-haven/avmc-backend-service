# 10 · 配置校验与错误体系

> 源节：§28 配置 · §29 错误体系
> 适用阶段：Phase 1, 8
> 受众：所有人
> 关键性：**错误契约决定用户能否正确处理故障**

---

## 1. Error 体系（**1.2 合并**）

### 1.2 Sentinel 错误

```go
var (
    ErrInvalidConfig = errors.New("lexnorm: invalid config")
    ErrInvalidSpan   = errors.New("lexnorm: invalid span")
    ErrConflict      = errors.New("lexnorm: conflict")
    ErrRuntime       = errors.New("lexnorm: runtime resolution failed")
)
```

### 1.0 vs 1.1 vs 1.2 对照

| 错误 | 1.0 | 1.1 | **1.2** | 说明 |
|---|:--:|:--:|:--:|---|
| `ErrProcessorNotFound` | ✅ | ❌ | ❌ | 1.1 取消；1.2 不恢复 |
| `ErrInvalidConfig` | ✅ | ✅ | ✅ | 通用 |
| `ErrTextTooLarge` | ✅ | ❌ | ❌ | 1.1 取消；1.2 不恢复 |
| `ErrInvalidSpan` | ❌ | ✅ | ✅ | 1.1 引入 |
| `ErrConflict` | ❌ | ✅ | ✅ | 1.1 引入；用于 Lexicon / Lock 冲突 |
| `ErrRuntime` | ❌ | ✅ | ✅ | 1.1 引入；用于 ProfileResolver 失败 |

### 取消的理由

- `ErrProcessorNotFound`：Registry 在核心 API 外，应由 Registry 自行定义
- `ErrTextTooLarge`：可由 Engine 配置层用通用 error 表达；不需要 sentinel
- `ErrProcessorNotFound` 在 1.2 仍未恢复——保持核心包精简

## 2. Processor 错误

```go
type ProcessorError struct {
    Name string
    Op   string
    Err  error

func (e *ProcessorError) Error() string { ... }
func (e *ProcessorError) Unwrap() error { return e.Err }
```

### 判定支持

```go
errors.Is(err, lexnorm.ErrInvalidConfig)
errors.As(err, &target)
```

## 3. 边界

### 核心库不得引入 Kratos Error

业务系统需要 Kratos 错误码时，在业务侧转换：

```go
// 业务侧
func toBizCode(err error) biz.Code {
    var pe *lexnorm.ProcessorError
    if errors.As(err, &pe) {
        switch {
        case errors.Is(pe.Err, lexnorm.ErrInvalidConfig):
            return biz.CodeInvalidConfig
        case errors.Is(pe.Err, lexnorm.ErrInvalidSpan):
            return biz.CodeInvalidInput
        case errors.Is(pe.Err, lexnorm.ErrConflict):
            return biz.CodeConflict
        case errors.Is(pe.Err, lexnorm.ErrRuntime):
            return biz.CodeUnavailable
        }
    }
    return biz.CodeInternal
}
```

## 4. Config 校验

```go
func (c Config) Validate() error
```

### 硬规则

**非法配置**：

```text
New → error
```

**不得**：

```text
非法值
 ↓
静默 Clamp
 ↓
继续执行
```

> 这是 `00 §2.3 Explicit over Implicit` 的具体落地。

### 例外：显式宽容模式

如果调用方确实需要宽容行为，应显式提供：

```text
Lenient Configuration
```

```go
opt := lexnorm.WithLenientConfig()  // 显式声明后允许 Clamp
```

> 但默认仍为**严格模式**。

### Confidence 校验

```text
0.0 ≤ Confidence ≤ 1.0
```

越界 → 返回 `ErrInvalidConfig`，**不静默 Clamp 到 0**。

### 浮点特殊值

| 值 | 处理 |
|---|---|
| NaN | 返回 `ErrInvalidConfig` |
| +Inf | 返回 `ErrInvalidConfig` |
| -Inf | 返回 `ErrInvalidConfig` |

> 浮点特殊值同样视为非法。

## 5. New 返回 error（**D2 决议**）

```go
func New(opts ...Option) (*Engine, error)
```

构造期校验失败场景：

| 场景 | error |
|---|---|
| Pipeline 为空 | `ErrInvalidConfig` |
| Profile 不存在 | `ErrInvalidConfig` |
| Lexicon 为 nil | `ErrInvalidConfig` |
| Middleware / Hook 重复注册 | `ErrInvalidConfig` |
| ErrorPolicy 非法值 | `ErrInvalidConfig` |
| ProfileResolver 与 Profiles 同时设置 | `ErrInvalidConfig` |

**D2 决议理由**：构造期 fail-fast 比延迟到首次 Normalize 更安全；用户能立即看到配置错误，无需等到运行时。

## 6. ErrorPolicy 与错误处理

```go
type ErrorPolicy uint8

const (
    ContinueOnError ErrorPolicy = iota
    FailFast
)
```

### ContinueOnError（默认）

```text
Processor Error
    ↓
记录错误
    ↓
继续后续 Processor
    ↓
Result.Status = Partial
```

### FailFast

```text
Processor Error
    ↓
立即停止后续步骤
    ↓
Result.Status = Canceled 或 Failed
```

### 与 Result 的关系

| ErrorPolicy | 单步 error 时 Result.Status | Result.Errors | Result.Steps |
|---|---|---|---|
| `ContinueOnError` | `Partial` | error 追加到 `Errors` | 包含失败的步骤 |
| `FailFast` | `Canceled` 或 `Failed` | error 写入 `Errors` 后停止 | 仅含已完成的步骤 |

### 与 Result.Err 的关系

```go
// Result.Errors 是全部错误列表
// Result.Err 是聚合视图（errors.Join(Errors...)）
```

> 调用方可用 `errors.Is/As` 判定；`Result.Err` 便于快速 `if err != nil` 判定。

## 7. Middleware 错误处理

### 推荐实践

- Middleware **不要吞掉 error**：`return nil` 会让 Pipeline 误判成功
- Middleware 应**透传 error**，由 Pipeline 统一处理
- Middleware 自身的 panic 由 `Recover()` Middleware 统一捕获

```go
func MyMiddleware() lexnorm.Middleware {
    return func(next lexnorm.Handler) lexnorm.Handler {
        return func(ctx context.Context, s *lexnorm.State) error {
            err := next(ctx, s)
            // ✅ 透传
            return err
        }
    }
}
```

## 8. Hook 错误处理

Hook **不影响**规范结果。

| 维度 | 约束 |
|---|---|
| Hook 内部 panic | Hook 自己 recover，不得冒泡 |
| Hook 内部 error | 吞掉或记日志，不得返回 |
| Hook 阻塞 | 不得长时间阻塞 Pipeline |

> 详见 [08-横切能力Middleware与Hook](08-横切能力Middleware与Hook.md) §7。

## 9. Configuration 与业务规则

业务规则**不能写死在 Processor**。

### 反例

```go
// ❌ Processor 内部硬编码业务规则
func (p *DeterministicProcessor) Process(...) {
    if span.Text == "个种籽" {
        state.Replace(span, "颗种籽", ...)
    }
}
```

### 正例

```yaml
# config.yaml
processors:
  - name: deterministic
    config:
      rules:
        - from: "个种籽"
          to: "颗种籽"
```

Processor 负责执行规则。**业务系统负责管理规则来源。**

## 10. Processor 配置原则

每个 Processor：

```text
Config
 ↓
Validate
 ↓
Build
 ↓
Runtime Read Only
```

### 运行时行为

- **运行期间不修改配置**
- **配置更新通过重新创建 Processor / Pipeline / Engine 或对应 Snapshot 完成**
- **Lexicon 热更新 ≠ Processor 配置热更新**

## 11. State.Replace / Suggest / Lock 错误返回（**1.2 修订**）

```go
func (s *State) Replace(span Span, to string, meta ChangeMeta) error
func (s *State) Suggest(span Span, to string, meta ChangeMeta) error
func (s *State) Lock(span Span) error
```

### 错误返回对照表

| 调用 | 失败条件 | 返回 |
|---|---|---|
| `Replace` | span 越界 | `ErrInvalidSpan` |
| `Replace` | span 与 Locked 重叠 | `ErrConflict` |
| `Replace` | Confidence 越界 | `ErrInvalidConfig` |
| `Suggest` | span 越界 | `ErrInvalidSpan` |
| `Suggest` | Confidence 越界 | `ErrInvalidConfig` |
| `Lock` | span 越界 | `ErrInvalidSpan` |

> 详见 [05-State与保护区机制](05-State与保护区机制.md) §4-§6。

## 12. 错误码设计原则

### 命名

- 包级 sentinel：`ErrXxx`
- 类型化错误：`XxxError`
- 错误字段：`Name` / `Op` / `Err`

### 信息层级

| 字段 | 作用 |
|---|---|
| `Name` | Processor 标识（用于溯源） |
| `Op` | 操作阶段（`new` / `process` / `validate`） |
| `Err` | 根因 |

### 不要

- ❌ 在 Error 中携带敏感数据（用户文本、Token）
- ❌ 把 Error.String() 作为用户提示文案
- ❌ 用 Error 传递正常控制流（应用 nil error 表达成功）

## 13. 测试要求

| 测试 | 验证 |
|---|---|
| Sentinel errors | `errors.Is(err, lexnorm.ErrXxx)` 命中 |
| `errors.As` | `*ProcessorError` 可被取出 |
| 非法 Config | `New(...)` 返回 `ErrInvalidConfig`（**D2 决议**） |
| 越界 Confidence | 同上 |
| ContinueOnError 聚合 | `Result.Errors` 包含所有步骤的错误，`Result.Err` 是聚合视图 |
| FailFast 中断 | 后续 Processor 未执行 |
| State.Replace 命中 Locked | 返回 `ErrConflict` |
| State.Replace 越界 | 返回 `ErrInvalidSpan` |
