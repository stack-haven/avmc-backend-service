# 02 · 核心领域模型

> 源节：§4 核心对象模型 · §10 Action · §17 Result · §18 Status · §20 Certainty 与 Order
> 适用阶段：Phase 1
> 受众：核心开发者
> 关键性：**API 稳定契约**，v1 后冻结

---

## 1. 九大核心对象

```text
Processor        ── 最小规范能力单元
Pipeline         ── 多个 Processor 的组合器（本身也是 Processor；interface）
Engine           ── 运行体系 Facade
Profile          ── 规范运行上下文的具名身份（含 Version）
ProfileResolver  ── 业务系统注入的多 Profile 路由抽象
Runtime          ── 一次 Normalize 调用的完整不可变快照
Lexicon          ── 规范知识来源（来自 LexiconSource 组合）
LexiconSource    ── 规范化知识的来源（业务系统、平台、用户、外部）
State            ── 单次规范运行的工作状态（Request Scoped）
Result           ── 规范执行最终结果（含 Original / Duration / Steps / Runtime）
```

### 核心关系

```text
ProfileResolver
    │ Resolve(profileID) → Runtime
    ▼
   Runtime (Profile + Lexicon + Pipeline + Config + Versions)
    │
    ▼
   Engine.Normalize(ctx, text)
    │
    ▼
   Pipeline.Process(state)
    │
    ├── Processor A → State.Replace/Suggest
    ├── Processor B → State.Replace/Suggest
    └── Processor C → State.Replace/Suggest
    │
    ▼
   Result (Text + Original + Changes + Status + RuntimeInfo)
```

Engine 不负责实现具体规范算法。

## 3. Pipeline（**1.2 升级为 interface**）

```go
type Pipeline interface {
    Processor
    Processors() []Processor
}

// 默认实现（包内）
type pipeline struct {
    processors []Processor
}

func NewPipeline(processors ...Processor) Pipeline
```

### 1.2 关键升级

| 版本 | Pipeline 类型 | 影响 |
|---|---|---|
| 1.0 | `struct`（具体类型） | 用户不能自定义 Pipeline |
| **1.2** | **`interface`** | **用户可实现自定义 Pipeline**（如条件分支、并行执行） |

### Pipeline 必须满足

- **顺序明确**
- **可裁剪**
- **可插入**
- **可替换**
- **可独立执行**
- **不依赖 Engine**

## 5. Profile

```go
type ProfileID string

type Profile struct {
    ID      ProfileID
    Version string
}
```

### Profile 边界

**Profile 不是 Tenant**。它是通用的运行上下文标识。

**Profile 不负责**：

- 数据库存储
- 权限
- 用户
- 生命周期
- 多租户

> 详见 [07-Engine与Profile](07-Engine与Profile.md)。

## 6. Runtime Snapshot（1.1 新增 / 1.2 采纳）

```go
type Runtime struct {
    Profile           Profile
    Lexicon           Lexicon
    Pipeline          Pipeline
    Config            Config
    ProfileVersion    string
    LexiconVersion    string
    PipelineVersion   string
    ProcessorVersions map[string]string
}
```

**Runtime 在一次请求开始时确定**。请求执行过程中不得切换 Snapshot。

**架构不变量**：一次请求必须使用一致 Runtime Snapshot（不变量 8）。

> 详见 [07-Engine与Profile](07-Engine与Profile.md) §4。

## 7. Lexicon

```go
type Lexicon interface {
    Entry(id EntryID) (Entry, bool)

    All(func(Entry) bool)
    Matcher() *Matcher
    Len() int
    Version() string
}
```

**Lexicon 不负责**：数据库存储 / 同步 / 权限 / API / 多租户 / 生命周期。

## 8. LexiconSource（1.1 新增 / 1.2 采纳）

```go
type LexiconSource interface {
    Version() string
    Entries(yield func(Entry) bool)
    Relations(yield func(Relation) bool)
}
```

**LexiconSource 是 Lexicon 知识的来源抽象**：

- 平台标准数据
- 业务系统数据
- 用户配置数据
- 外部系统同步数据

业务系统负责把自己的数据源转换为 `LexiconSource`，核心包不定义具体业务名称。

> 详见 [06-Lexicon与热更新](06-Lexicon与热更新.md) §4。

## 9. State

```go
type State struct {
    // private
}
```

- **State 是 Request Scoped 对象**
- **同一个 State 不允许被多个 Goroutine 并发修改**
- **State 内部字段必须保持私有**

### State 公开能力（1.2 修订）

```go
func (s *State) Text() string
func (s *State) Lexicon() Lexicon
func (s *State) Config() Config

// 1.2 决议：改为 error 返回（D2 同源原则）
func (s *State) Replace(span Span, to string, meta ChangeMeta) error
func (s *State) Suggest(span Span, to string, meta ChangeMeta) error
func (s *State) Lock(span Span) error
func (s *State) IsLocked(span Span) bool
```

### 1.0 → 1.2 API 变更

| 方法 | 1.0 | 1.2 | 说明 |
|---|:--:|:--:|---|
| `Text()` | ✅ | ✅ | 不变 |
| `Lexicon()` | ✅ | ✅ | 不变 |
| `Config()` | ✅ | ✅ | 不变 |
| `Original()` | ✅ | ❌ | 移除；信息保留在 `Result.Original` |
| `Profile()` | ✅ | ❌ | 移除；信息在 `Runtime.Profile` |
| `Changes()` | ✅ | ❌ | 移除；通过 `Result.Changes` 暴露 |
| `Replace()` | 无返回 | **error** | 显式错误返回 |
| `Suggest()` | 无返回 | **error** | 显式错误返回 |
| `Lock()` | 无返回 | **error** | 显式错误返回 |
| `IsLocked()` | ✅ | ✅ | 不变 |

> 详见 [05-State与保护区机制](05-State与保护区机制.md)。

## 10. Result（1.2 合并字段，D3 决议）

```go
type Result struct {
    Text        string         // 规范化后文本
    Original    string         // 原始文本（1.0 保留）
    Status      Status
    Changes     []Change       // 全部 Change（Applied + Suggested + Skipped）
    Suggestions []Change       // Applied=false 的 Change（独立字段，1.1 新增）
    Errors      []error        // 全部 Processor 错误（1.1 新增）
    Err         error          // errors.Join(Errors...) 聚合（1.0 保留）
    Duration    time.Duration  // 总耗时（1.0 保留）
    Steps       []StepTiming   // 每步耗时（1.0 保留，确定顺序、零分配）
    Runtime     RuntimeInfo    // 完整运行快照（1.1 新增）
}

type RuntimeInfo struct {
    ProfileID         ProfileID
    ProfileVersion    string
    LexiconVersion    string
    PipelineVersion   string
    ProcessorVersions map[string]string
}
```

### 1.0 vs 1.1 vs 1.2 Result 对照

| 字段 | 1.0 | 1.1 | **1.2** | 来源决策 |
|---|:--:|:--:|:--:|---|
| `Text` | ✅ | ✅ | ✅ | 通用 |
| `Original` | ✅ | ❌ | ✅ | D3 保留 |
| `Status` | ✅ | ✅ | ✅ | 通用 |
| `Changes` | ✅ | ✅ | ✅ | 通用 |
| `Suggestions` | ❌ | ✅ | ✅ | 1.1 引入 |
| `Errors` | ❌ | ✅ | ✅ | 1.1 引入 |
| `Err`（聚合） | ✅ | ❌ | ✅ | D3 保留 |
| `Duration` | ✅ | ❌ | ✅ | D3 保留 |
| `Steps` | ✅ | ❌ | ✅ | D3 保留 |
| `Runtime` | ❌ | ✅ | ✅ | 1.1 引入 |

> **1.2 合并策略**：`Suggestions` / `Errors` / `Runtime` 是 1.1 引入的更精细字段；`Original` / `Err` / `Duration` / `Steps` 是 1.0 保留的有价值元数据。两套字段并存，各有用途。

## 11. Status（1.2 包含 1.1 新增的 StatusFailed）

```go
type Status int

const (
    StatusSuccess Status = iota
    StatusPartial
    StatusCanceled
    StatusFailed     // 1.1 新增 / 1.2 采纳
)
```

| Status | 含义 |
|---|---|
| `StatusSuccess` | 所有必要 Processor 正常完成 |
| `StatusPartial` | 部分 Processor 失败，但仍产生可用结果 |
| `StatusCanceled` | 调用被 Context 取消 |
| `StatusFailed` | 无法形成有效结果（Lexicon 缺失、Runtime 解析失败等） |

**默认原则**：单个 Processor Failure → `Partial`；无法继续运行的基础错误 → `Failed`。

## 12. Change（1.2 字段扩展）

```go
type Change struct {
    Span             Span
    From             string
    To               string
    Action           Action
    Kind             ChangeKind    // 1.2 重命名: Kind → ChangeKind
    Source           string        // 1.2 决议: 1.0 枚举 → 1.1 string
    RuleID           string        // 1.1 新增
    EntryID          string        // 1.1 新增
    Processor        string        // 1.1 新增
    ProcessorVersion string        // 1.1 新增
    Confidence       float64
    Applied          bool
    Reason           string
}
```

### 字段语义

| 字段 | 作用 |
|---|---|
| `Span` | 在 Original 中的字节区间 |
| `From` / `To` | 修改前/后文本 |
| `Action` | 修改类型（替换/删除/建议） |
| `Kind` | 改写分类（详见 §15） |
| `Source` | 知识来源（人工/自动抽取/第三方，**string** 字段） |
| `RuleID` | 命中的规则 ID（用于审计） |
| `EntryID` | 命中的 Lexicon Entry ID（用于审计） |
| `Processor` | 产生此 Change 的 Processor 名称 |
| `ProcessorVersion` | Processor 版本（用于重放） |
| `Confidence` | 置信度 [0.0, 1.0] |
| `Applied` | true=已应用 / false=仅建议 |
| `Reason` | 人类可读的决策依据 |

### Change 必须能够区分

```text
Applied (Action=ActionReplace/ActionRemove, Applied=true)
Suggested (Action=ActionSuggest, Applied=false)
Skipped (不产生 Change 记录)
```

## 13. Action

```go
type Action uint8

const (
    ActionReplace Action = iota
    ActionRemove
    ActionSuggest
)
```

**未来新增 Action 必须保持向后兼容**：

- 只能追加（不修改现有常量值）
- 不重用已弃用的编号

## 14. Span

```go
type Span struct {
    Start int
    End   int
}
```

采用**半开区间**：

```text
[Start, End)
```

**位置统一采用 Original UTF-8 字节偏移**（1.2 决议：吸收 1.0 严格表述，1.1 弱化被纠正）。

> **重要约束**：Span 始终指向 `Original` 文本的偏移，不指向 `Text` 当前偏移。
> State 内部负责维护 `Original → Text` 的偏移映射。
> Processor **禁止**自己维护偏移。

## 15. Certainty（1.2 简化为 3 档）

```go
type Certainty int

const (
    CertaintyHigh Certainty = iota
    CertaintyMedium
    CertaintyLow
)
```

### 1.0 → 1.2 变化

| 1.0 | 1.2 |
|---|---|
| CertaintyUnknown | ❌ 取消 |
| CertaintyLow | ✅ 保留 |
| CertaintyMedium | ✅ 保留 |
| CertaintyHigh | ✅ 保留 |
| CertaintyDeterministic | ❌ 取消 |

**取消理由**：`CertaintyUnknown` 在声明式使用中无意义；`CertaintyDeterministic` 与 `CertaintyHigh` 在排序时等价。

### Certainty 与 Order 的关系

| 概念 | 决定权 | 作用 |
|---|---|---|
| **Order** | Pipeline 显式决定 | 实际执行顺序 |
| **Certainty** | Processor 自声明 | 辅助 Standard Preset 设计、辅助决策分级 |

> **显式 Pipeline Order > 默认推荐 Order > Certainty 推导**

## 16. Decision

```text
Apply
Suggest
Skip
```

### Apply

满足自动规范条件（Confidence ≥ `auto_threshold`）。

### Suggest

有较强候选，但不满足自动修改条件（`suggest_threshold` ≤ Confidence < `auto_threshold`）。

### Skip

置信度或条件不足（Confidence < `suggest_threshold`）。

### 与 Change 的映射

| Decision | Change.Action | Change.Applied | Result 字段 |
|---|---|:--:|---|
| Apply | `ActionReplace` / `ActionRemove` | `true` | `Changes` |
| Suggest | `ActionSuggest` | `false` | `Changes` + `Suggestions` |
| Skip | （不生成 Change） | — | — |

---

## 17. Confidence

Confidence 使用 `float64`，约定 `0.0 ≤ Confidence ≤ 1.0`。

**不得在配置非法时静默 Clamp**：

```text
Confidence = 1.5
   ↓
Config.Validate() → error
   ↓
New → ErrInvalidConfig
```

> 详见 [10-配置校验与错误体系](10-配置校验与错误体系.md) §3。

## 18. 结果不可变原则

Result 对外表现为**值语义**。

```text
State (可变)
 ↓
Pipeline 完成
 ↓
Result Snapshot（不可变）
```

### 实现要点

- `Result` 必须是值类型（或返回时深拷贝内部 slice）
- `Result` 内部不持有 `*State` 引用
- 调用方可以安全地并发读取同一个 `Result`

## 19. 对象一览速查表（1.2 修订）

| 对象 | 包位置 | 是否接口 | 是否可并发 | 是否可变 |
|---|---|:--:|:--:|:--:|
| Processor | 根包 | 是（interface） | 实例共享 ✓ | 不可变 |
| Pipeline | 根包 | **是（interface，1.2 升级）** | 实例共享 ✓ | 不可变 |
| Engine | 根包 | 是（struct，Facade） | 实例共享 ✓ | 内部 atomic |
| Profile | 根包 | 值类型 | 值传递 | 不可变 |
| ProfileResolver | 根包 | 是（interface，1.1 新增） | 实例共享 ✓ | 不可变 |
| Runtime | 根包 | struct | 实例共享 ✓ | **不可变** |
| Lexicon | `lexicon/` | 是（interface） | 实例共享 ✓ | Runtime 只读 |
| LexiconSource | `lexicon/` | 是（interface，1.1 新增） | 实例共享 ✓ | 不可变 |
| State | 根包 | 是（struct） | 单 goroutine | 单请求可变 |
| Result | 根包 | 值类型 | 值传递 | 不可变 |
| Change | 根包 | 值类型 | 值传递 | 不可变 |
| Span | 根包 | 值类型 | 值传递 | 不可变 |
