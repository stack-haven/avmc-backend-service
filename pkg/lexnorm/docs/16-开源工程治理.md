## 1. 开源工程清单（§74）

### 必须包含

```text
LICENSE
README.md
README.zh-CN.md
CHANGELOG.md
CONTRIBUTING.md
SECURITY.md
CODE_OF_CONDUCT.md
```

### 文档要求

- 每个公共包必须有完整 **GoDoc**
- 所有导出 API 必须有规范注释（`// Name ...` 格式）
- 英文为默认语言，提供中文翻译

### 治理文件

| 文件 | 内容要点 |
|---|---|
| `LICENSE` | Apache-2.0 |
| `README.md` | 项目简介 · 安装 · 快速上手 · 链接到 godoc |
| `README.zh-CN.md` | 中文版 README（与英文同步） |
| `CHANGELOG.md` | Keep a Changelog 格式 |
| `CONTRIBUTING.md` | 贡献流程 · Code Review 流程 · 不变量清单 |
| `SECURITY.md` | 漏洞上报流程 · CVE 策略 |
| `CODE_OF_CONDUCT.md` | Contributor Covenant v2.1 |

## 2. 第三方依赖（§50）

### 主模块

```text
github.com/stack-haven/lexnorm
```

**必须只依赖 Go Standard Library。**

### 禁止核心模块直接依赖

```text
kratos
gorm
ent
redis
mysql
otel
LLM SDK
```

### 基础设施隔离

需要第三方基础设施时使用**独立 submodule**：

```text
github.com/stack-haven/lexnorm/hooks/otel   ← 独立 go.mod
github.com/stack-haven/lexnorm/hooks/redis  ← 独立 go.mod（若未来需要）
```

> 验证命令：

```bash
go list -deps github.com/stack-haven/lexnorm | \
    grep -v "^github.com/stack-haven/lexnorm/" | \
    grep -v "^internal/" | \
    grep -v "vendor/"
```

期望输出：仅 stdlib 路径。

## 3. Go 版本（§75）

### 初始版本

```go
go 1.22
```

### 约束

- 避免为了语言特性而过度提高最低版本
- 若实际使用 Go 1.23+ 特性，重新评估最低版本
- **不得为了追求新 API 而破坏生态兼容性**

### 兼容性矩阵

| Go 版本 | 支持状态 |
|---|---|
| 1.22 | 最低支持 |
| 1.23 | 支持 |
| 1.24 | 支持 |
| 1.25 | 支持 |

## 4. API 稳定性（§76）

### 阶段划分

| 阶段 | 策略 |
|---|---|
| v0.x（开发期） | 允许快速迭代 + API 变更 |
| v1.0+ | 重点 API 冻结 |

### v1.0 冻结的 API

```text
Processor
Pipeline
Engine
State
Result
Lexicon
```

### 永久稳定

```go
Processor.Process(ctx, *State) error
```

> 属于核心稳定接口。

### 兼容性策略

| 变更类型 | 策略 |
|---|---|
| 内部实现 | 自由变更 |
| Bug 修复 | 直接修复 |
| 新增方法 | 添加，旧方法保留 Deprecated |
| 新增类型 | 自由添加 |
| 修改签名 | 必须 major version bump |
| 删除 API | 必须 major version bump + 至少 1 个 minor 的 Deprecated 期 |

## 5. CI 矩阵

### 必须覆盖

| 维度 | 范围 |
|---|---|
| Go 版本 | 1.22 ~ 1.25 |
| OS | linux / darwin / windows |
| Race | 启用 |
| Lint | golangci-lint 启用 |
| Coverage | 启用 |

### CI 阶段

```yaml
jobs:
  lint:
    - gofmt -l .
    - golangci-lint run
  test:
    - go vet ./...
    - go test -race -coverprofile=cover.out ./...
  benchmark:
    - go test -bench=. -benchmem -count=10 ./...
  build:
    - go build ./...
    - go build ./...
```

## 6. 版本号管理

### Semver

```text
vMAJOR.MINOR.PATCH
```

### tag 流程

1. 在 `main` 分支合并 PR
2. 更新 `CHANGELOG.md`
3. 打 tag：`git tag -a v0.1.0 -m "..."`
4. 推送 tag：`git push origin v0.1.0`
5. CI 自动构建 + Release

### 推荐节奏

| 版本 | 目标 |
|---|---|
| v0.1.0 | 核心 API 可用 |
| v0.5.0 | 全部内置 Processor 完成 |
| v1.0.0 | API 冻结 + Benchmark 达标 + 文档完整 |

## 7. 包名规范

### 禁止

- 下划线包名（`my_pkg`）
- 缩写（`util`、`helpers`、`common`）
- 与 stdlib 冲突（`http`、`io`）

### 推荐

```text
lexnorm              ← 根包
lexnorm/processor    ← 子包集合
lexnorm/processor/clean
lexnorm/lexicon
lexnorm/match
lexnorm/preset
lexnorm/hooks
lexnorm/internal     ← 不导出
```

## 8. 导出符号注释规范

每个导出符号必须有：

```go
// Foo 是 XXX 的简明描述。
//
// 详细行为说明，包含：
//   - 调用约束
//   - 并发安全性
//   - 错误语义
//   - 示例（可选）
//
// Foo 必须在 New 之后调用。
func Foo() error { ... }
```

### 注释模板

```go
// Package foo 提供 XXX 能力。
//
// # 概述
//
// 一句话定义。
//
// # 快速上手
//
// 示例代码块（可运行）。
//
// # 并发安全
//
// Foo 是并发安全的；Bar 不是。
package foo
```

## 9. Example 函数

每个公共包必须提供至少一个可运行的 Example：

```go
func ExampleNew() {
    eng, _ := lexnorm.New(lexnorm.WithPipeline(pipeline))
    res, _ := eng.Normalize(context.Background(), "呃, hello")
    fmt.Println(res.Text)
    // Output: hello
}
```

> `pkg.go.dev` 首页会展示 Example。

## 11. 安全策略

### SECURITY.md

```markdown
# Security Policy

## Supported Versions

| Version | Supported          |
|---------|--------------------|
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

请通过 security@example.com 上报，不在 GitHub Issues 公开。
```

### 不在核心库做的事

- 不收集用户数据
- 不内置任何凭据
- 不调用任何外部网络（除 LLM Processor 用户自行注入）
- Hook 默认不打文本内容
