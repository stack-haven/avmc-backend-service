# 20 · 词条字段说明（开发者指南）

> 本文档说明 ark-lexnorm 词库 JSON 的完整字段约定，配合
> `example/09-compare-engine-vs-llm` 使用。

---

## 1. 文件清单

| 文件 | 用途 | 数量级 |
|---|---|---|
| `data/user.json` | 人名词库（来自 HR/IM 系统） | 几十 ~ 几千条 |
| `data/dept.json` | 部门/组织名词库 | 几十 ~ 几百条 |
| `data/system.json` | 业务术语词库（含 Pipeline 元数据） | 几十 ~ 几百条 |

> 三个文件**可独立使用**也**可合并**：通过 `lexicon.Compose()` 合并为单一 Lexicon。

---

## 2. 顶层结构

```json
{
  "version": "user-2025-09-08",
  "source": "admin-api/qua/member-extended/page",
  "entries": [ /* Entry 数组 */ ],
  "meta": { /* 文件级元数据，可选 */ }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `version` | string | ✅ | 词库版本号。词库更新时必变（用于 cache 失效）。|
| `source` | string | ✅ | 数据来源标识（API 名 / 文件路径 / 人工标注）。audit 用。|
| `entries` | Entry[] | ✅ | 词条数组。|
| `meta` | object | ❌ | 文件级元数据（如 Pipeline 配置、来源统计）。不参与匹配。|

---

## 3. Entry 词条

```json
{
  "id": "user-1904450235179954177-田华",
  "text": "田华",
  "pinyin": "tian hua",
  "variants": [ /* Variant 数组 */ ],
  "meta": { "dept_id": "1904450235179954177", "dept_name": "万康盛鼎集团" }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 全局唯一 ID。约定：`{类型}-{部门ID}-{名称}` 或 `{prefix}-{name}` |
| `text` | string | ✅ | **canonical（标准）写法**。引擎会把所有 variant 替换为这个。|
| `pinyin` | string | ❌ | 拼音（空格分隔每个汉字）。可选，便于 audit 和人工 review。**不参与匹配**。|
| `variants` | Variant[] | ✅ | 同义词 / 错字 / 别名数组。可为空 `[]`。|
| `meta` | object | ❌ | 词条元数据（如部门、职位、分类）。不参与匹配，但可被 audit pipeline 引用。|

### 3.1 命名约定

| 词条类型 | ID 前缀 | 示例 |
|---|---|---|
| 用户/人名 | `user-` | `user-1904450235179954177-田华` |
| 部门 | `dept-` | `dept-1904450235179954177` |
| 业务术语 | `term-` | `term-jinzhongzi` |
| 别名（昵称/称谓） | `alias-` | `alias-tiangong`（可选）|

> ⚠️ **同一 Lexicon 中 `id` 必须唯一**。两个不同 dept 的同名 dept 需要在 id 中加 dept_id 区分。

### 3.2 text 字段

- **就是引擎的目标输出**——所有 variant 都会被替换为 `text`
- 中文为主，可包含 ASCII（PPT、URL 等）
- 长度建议 1-8 个字符
- ⚠️ **不要把 text 设为另一个 entry 的 variant**（会破坏数据一致性）

## 4. Variant 变体

```json
{
  "text": "田工",
  "kind": "alias",
  "confidence": 0.85,
  "source": "manual-title"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | ✅ | 变体文本。引擎扫到原文里的这个 text，会替换为 entry.text。|
| `kind` | string | ✅ | 变体类型（决定哪个 processor 消费），见 [§5](#5-variant-kind-类型)。|
| `confidence` | float | ✅ | 匹配置信度 [0.0, 1.0]。<br/>- 0.95+ → Apply（自动替换）<br/>- 0.70-0.95 → Suggest（仅建议）<br/>- < 0.70 → Skip<br/>详见 [§6](#6-confidence-阈值策略)。|
| `source` | string | ❌ | 变体来源（`manual-curated` / `auto-pinyin` / `auto-mined` / `manual-asr` / `manual-homophone` / `manual-title`）。audit 用。|

### 4.1 字段使用建议

- `text` 不能为空字符串
- `text == entry.text` 的变体会被引擎自动跳过（`if v.Text == e.Text { continue }`）
- `confidence` 缺省时为 0.0 → **silent skip**（这是个陷阱，详见 [§6](#6-confidence-阈值策略)）

---

## 5. Variant Kind 类型

| kind 字符串 | 引擎消费 processor | 语义 | 典型场景 |
|---|---|---|---|
| `alias` | `alias` | 同义词/别名，可互换 | "田工"→"田华" |
| `correction` | `deterministic` | 确定性错字 | "再"→"在"（笔误）|
| `homophone` | ⚠️ 仅 `.Confidence` 被读 | 同音异字 | "梦莲"→"孟莲" |
| `approximate` | `fuzzy` | 近似匹配（编辑距离 / n-gram）| "金种仔"→"金种籽" |

⚠️ `kind:homophone` 在当前工具包中是 **隐性损坏**：
- `Variant{Homophone}.Confidence` 被 `pinyin.go::defaultConfidence()` 读取（作为 entry 默认 conf）
- 但 `Variant{Homophone}.Text` **完全不被任何 processor 消费**——会 `silent skip`

→ 1.2.0 之前推荐使用 `kind:approximate` 作为变通方案（语义不准确，但能命中）。详见 `docs/19-工具包缺陷清单.md` D-2。

### 5.1 kind 选择决策树

```
你的变体和 canonical 是什么关系？
│
├── 完全可互换（同一个词的不同写法）
│   └── alias
│       例：田工 ↔ 田华
│
├── 同音但不同字
│   ├── 严格同音（拼音完全相同）
│   │   └── homophone ← 工具包缺陷 D-2：暂用 approximate 变通
│   │
│   └── 音相近但非完全同音
│       └── approximate
│           例：金种仔 ↔ 金种籽（zǎi ≈ zǐ）
│
├── 错字/笔误（手抖/OCR/ASR 错读）
│   ├── 已知模式（单字替换）
│   │   └── correction（待实现）
│   │
│   └── 模糊匹配
│       └── approximate
│           例：菌种子 ↔ 黑种籽（完全错读）
│
└── 简称/缩略
    └── alias
        例：万康盛鼎 ↔ 万康盛鼎集团（⚠️ 见 [§7 陷阱](#7-常见陷阱)）
```

## 6. Confidence 阈值策略

### 6.1 引擎默认阈值

| 阈值名 | 默认值 | 含义 |
|---|---|---|
| `AutoApplyThreshold` | 0.95 | ≥ 此值时**自动替换**（Apply）|
| `SuggestThreshold` | 0.65 | [0.65, 0.95) 时**记录建议**但不替换（Suggest）|
| < SuggestThreshold | — | 静默跳过（Skip）|

### 6.2 推荐置信度分档

| conf | 含义 | 建议场景 |
|---|---|---|
| **0.95** | 明确错字/同音 | 引擎应自动替换 |
| **0.85** | 模糊变体 | 仅记录（Suggest），人工审核 |
| **0.70** | 高风险（不同音 ASR 错读）| 仅记录，**慎用** |
| 0.50 | 极不确定 | 实际不应用 |
| 0.00 | 缺省 | ⚠️ silent skip！必须显式设置 |

### 6.3 silent skip 陷阱

```go
// fuzzy.go 注释明确说：
// If you want a Variant to be treated as "high confidence by default",
// set Confidence explicitly (e.g., 0.95). Fuzzy does NOT auto-promote
// 0.0 to any default; the engine philosophy is "explicit beats implicit".
```

**务必显式设置 confidence**，否则引擎会**静默忽略**这个 variant。

## 7. 常见陷阱

### 7.1 变体是 canonical 的子串 ⚠️

```json
// ❌ 错误
{ "text": "万康盛鼎集团", "variants": [{ "text": "万康盛鼎", ... }] }

// 输入 "万康盛鼎集团开会" → 输出 "万康盛鼎集团集团开会" ❌
// 原因：alias 处理器把 canonical 的子串也当作 variant 替换了

// ✅ 正确：不登记子串 variant
{ "text": "万康盛鼎集团", "variants": [] }
```

详见 `docs/19-工具包缺陷清单.md` D-1。

### 7.2 同名歧义

```json
// ❌ 错误：两个部门同名"万康广告"
{ "id": "dept-1", "text": "万康广告" }
{ "id": "dept-2", "text": "万康广告" }
// → builder 报错：duplicate canonical text

// ✅ 正确：合并同名 dept，path 作为 variant 消歧
{ "id": "dept-1", "text": "万康广告",
  "variants": [{ "text": "万康盛鼎集团/万康广告", "kind": "alias" }] }
```

### 7.3 跨词条 variant 冲突

```json
// ❌ 错误：同一个 variant 挂在两个 entry 下
{ "id": "term-a", "text": "A", "variants": [{ "text": "黑钟子", ... }] }
{ "id": "term-b", "text": "B", "variants": [{ "text": "黑钟子", ... }] }
// → Aho-Corasick 只接受第一次出现的映射

// ✅ 正确：每个 variant 唯一归属于一个 entry
```

### 7.4 不登记无意义变体

```json
// ❌ 错误：给 canonical 登记自己
{ "text": "金种籽", "variants": [{ "text": "金种籽", ... }] }
// 引擎会自动跳过（v.Text == e.Text），但污染数据

// ❌ 错误：登记与 entry 无关系的词
{ "text": "袁孟莲", "variants": [{ "text": "测试账号", ... }] }
// → 变体必须与 canonical 在语义/语音/拼写上有关系
```

## 9. 加载与使用（Go 代码）

```go
import (
    "github.com/stack-haven/lexnorm"
    "github.com/stack-haven/lexnorm/example/09-compare-engine-vs-llm/internal/lexjson"
)

// 1. 加载 JSON
userLex, _ := lexjson.LoadFile("data/user.json")
deptLex, _ := lexjson.LoadFile("data/dept.json")
sysLex, _ := lexjson.LoadFile("data/system.json")

// 2. 转为 lexnorm Entry
var allEntries []lexnorm.Entry
for _, e := range userLex.Entries {
    le, _ := lexjson.ToEntry(e)
    allEntries = append(allEntries, le)
}
// ... 同上

// 3. 构建 Lexicon（启用 pinyin 索引）
built, _ := lexicon.NewBuilderWithVersion("v1").
    Add(allEntries...).
    WithPinyin(myPinyinConverter{}).
    Build()

// 4. 配置 Pipeline
pipeline := lexnorm.NewPipeline(
    normalize.New(),
    alias.New(built),
    fuzzy.New(built),
)

// 5. 跑规范化
engine, _ := lexnorm.New(
    lexnorm.WithLexicon(built),
    lexnorm.WithPipeline(pipeline),
    lexnorm.WithConfig(lexnorm.Config{
        AutoApplyThreshold: 0.70, // 调整阈值
        SuggestThreshold:   0.50,
    }),
)
result, _ := engine.Normalize(ctx, "袁梦莲提交了报告")
// result.Text = "袁孟莲提交了报告"
```

完整示例见 `example/09-compare-engine-vs-llm/cmd/03-engine-test/main.go`。

## 11. 与 ark-lexnorm 工具包的对应关系

| JSON 字段 | Go 类型 | 来源 |
|---|---|---|
| `VariantJSON` | `lexicon.Variant` | `lexicon/lexicon.go` |
| `EntryJSON` | `lexicon.Entry` | `lexicon/lexicon.go` |
| `LexiconJSON` | `[]lexicon.LexiconSource` | `lexicon/source.go` |
| `kind` 字符串 | `lexicon.VariantKind` (uint8) | `lexicon/lexicon.go:48-67` |

| kind 字符串 | VariantKind 常量 | 当前 Processor |
|---|---|---|
| `alias` | `VariantAlias` | `alias` |
| `correction` | `VariantCorrection` | `deterministic` (需显式加入 pipeline) |
| `homophone` | `VariantHomophone` | `pinyin`（v1.1 整词路径，D-2 已修复；阈值以下降级 Suggest）|
| `approximate` | `VariantApproximate` | `fuzzy` |
| `contextual` | `VariantContextual`（v1.1 新增） | `ctxproc`（v1 只 Suggest） |

## 12. 验证清单（提交前自检）

- [ ] 所有 `id` 唯一
- [ ] 所有 `text` 不重复（不同 entry）
- [ ] 所有 `variant.text` 不为 entry 自己的 `text`
- [ ] **（v1.1）`variant.text` 不是自身 `text` 的子串**（如「万康盛鼎」⊂「万康盛鼎集团」会损坏文本）
- [ ] **（v1.1）`variant.text` 不与其他 entry 的 `text` 冲突**（会把他人正名改写）
- [ ] **（v1.1）`variant.text` 不跨 entry 重复**（消解结果任意且静默）

> 以上三条已由 `lexicon.Builder.Validate()` 自动检查（错误包
> `lexicon.ErrConflict`）；`Build()` 保持宽容，推荐构建前显式调用 Validate。
- [ ] 所有 `variant.text` 不为其他 entry 的 `text`（避免跨词条冲突）
- [ ] 所有 `variant.text` 不为 `entry.text` 的子串（D-1 陷阱）
- [ ] 所有 `variant.confidence` 显式设置（非 0）
- [ ] `pinyin` 字段与 `text` 一致（空格分隔每个汉字）
- [ ] 跑过 `cmd/07-stress-test`，无 panic（ERROR=0）
