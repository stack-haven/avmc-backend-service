**关键设计**：

1. **Apply / Suggest / Skip 三档决策**：
   - `confidence >= AutoApplyThreshold` → `State.Replace`（text 变化）

3. **Fuzzy 用 Aho-Corasick**：与 Alias / Deterministic 同架构，但处理 `Variant{Approximate}`。

4. **Context 作为骨架**：核心包不捆绑 LLM / ML 资源（D1: LLM 可选扩展）。应用代码可通过 Middleware / Hook 或自定义 Processor 添加实际逻辑。

5. **目录重命名**：`processor/context/` → `processor/ctxproc/` 以避免与 Go stdlib `context` 包冲突。

**关键设计**：

1. **Registry 独立性**（不变量 I6）：`lexnorm.NewRegistry()` 不依赖 Engine；`Build("name", cfg)` 即可构造 Processor。

2. **Descriptor 模式**：每个 Processor 包暴露 `Descriptor` 变量（`normalize.Descriptor` 等），用户 `Registry.Register()` 即可启用配置驱动。

3. **Preset 模式与 Lexicon 共存**：`WithPreset(preset)` 算 1 个 mode，可与 `WithLexicon(lex)` 同时使用（Preset 模式）。

4. **Per-Processor Hook**：`EventProcessorStart` / `EventProcessorEnd` 在 `runProcessors` 中触发，含 `Processor` / `ProcessorVersion` / `Error` / `Duration` 字段。

5. **Timeout Middleware**：`context.WithTimeout(ctx, d)` 包裹 Handler；Processor 需遵守 `ctx.Done()`。

6. **presets 子包**：避免根包与 processor 子包的循环导入；`Standard`/`HighAccuracy`/`Fast`/`ASR`/`OCR` 5 个 Preset 工厂。

### M11：LLM Processor（**可选扩展，D1 决议**）

## 2. 1.2 Coding Agent 执行规则（**§44，20 条**）

1. 先实现核心抽象，再实现具体 Processor。
2. 每完成一个 M 必须保证测试通过。
3. 不得为了实现具体业务而向核心包增加 Tenant、ASR、HR、Employee 等概念。
4. 不得绕过 `State.Replace` 直接修改文本。
5. 不得让 Processor 直接持有可变 Lexicon。
6. 不得让请求共享 State。
7. 不得让请求过程中切换 Runtime Snapshot。
8. 不得使用全局可变业务状态。
9. 不得为了方便引入第三方核心依赖。
10. 新增公开 API 必须同步增加 Example 或测试。
11. 修改核心接口必须检查所有 Processor、Pipeline、Engine 和测试。
12. 性能优化必须有 Benchmark 数据支撑。
13. 任何并发实现必须通过 Race Test。
14. 任何 Snapshot 发布必须先 Build、Validate，再 Atomic Swap。
15. 任何 Processor Failure 必须明确处理策略，不得静默吞错。
16. 所有可观测信息必须通过 Result / Change / Hook 等机制暴露。
17. 不得将业务系统的数据源直接注入核心执行链路。
18. **Runtime 是一次请求的一致性边界**。
19. **Lexicon Snapshot 是知识一致性边界**。
20. **Profile 是规范化上下文标识，不承担业务权限职责**。

## 3. 15 条架构不变量（**§42**）

> 以下规则必须加入 **Code Review Checklist**。

| # | 不变量 | 验证方法 |
|:--:|---|---|
| 1 | Processor 可以独立运行 | 单测脱离 Engine |
| 2 | Pipeline 本身是 Processor | `var _ Processor = (Pipeline)(nil)` |
| 3 | Engine 不承载业务状态 | grep 检查 Engine 内部不持有 Profile 数据 |
| 4 | State 不跨请求共享 | race test 覆盖 |
| 5 | Lexicon Runtime 只读 | 测试覆盖 Build 后不可写 |
| 6 | 文本修改只能通过 State.Replace | grep 检查 strings.ReplaceAll |
| 7 | Protected Span 必须阻止后续非法覆盖 | 场景 C 验证 |
| 8 | 一次请求必须使用一致 Runtime Snapshot | 场景 D 验证 |
| 9 | 相同 Input + 相同 Snapshot 应产生确定性结果 | Golden + 多次运行比对 |
| 10 | Processor 失败不能默认导致原始文本丢失 | 场景 E 验证 |
| 11 | Profile 不等于 Tenant | grep 检查 tenant 出现 |
| 12 | 核心包不得依赖业务系统 | grep 检查业务词 |
| 13 | 外部 Lexicon 数据必须经过 Builder 才能进入运行时 | Lexicon 构造路径验证 |
| 14 | Lexicon 更新必须原子发布 | M7 验证 |
| 15 | 旧 Snapshot 必须支持正在执行的请求完成 | 场景 D 验证 |
